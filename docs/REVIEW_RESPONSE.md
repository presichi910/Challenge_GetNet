# Response to the external review

The review was written about commit `8c66a85`, the single flattened commit the history was joined to (`0ef58a4`). That commit is the system as it was first delivered: it has JWT authentication with **HS256** and a shared secret, and it has none of these files: `app/agents/observe.py`, `app/agents/verifier.py`, `app/approvals.py`, `app/webhook.py`, `app/telemetry.py`, `app/jwks.py`, `app/guard.py`, `app/revocation.py`, `app/ratelimit.py`, `eval/rejudge.py`, `eval/persistent.py`, `infra/observability/alerts.yml`, `constraints.txt`.
You can check any of them with `git cat-file -e 8c66a85:<path>` (it fails for each of these files) and compare with the current tree. This page answers each finding with what the repository holds **now**, and says where the answer is incomplete.

Where each claim can be checked, file by file: [EVIDENCE.md](EVIDENCE.md). The numbers of the final run: the generated block in the [README](../README.md#results) and [FINAL_REPORT.md](FINAL_REPORT.md) (a draft). **No rate or pass rate is typed on this page**: every judge-based figure lives in a generated block, with the number of rows it is over.

Status words: **closed** (done and checked), **partially closed** (done in part, or done but not measured the way the finding asks), **open** (not done), **by design** (a decision, with its price).

## Notes under the table

**Why `REPLAN_MAX=0` is the default.** The configuration that was evaluated (the five repetitions of the final run, and the later smoke that proves the new code does nothing with the step off) has the step off. `docker compose` reads its settings from `.env`, which is a copy of `.env.example`, and that file sets `REPLAN_MAX=0` too, as does `app/config.py`. So what a person starts with `docker compose up` is the configuration the numbers belong to. The step with `REPLAN_MAX=2` has **mechanical** measurements (how often it fired, what it cost and which checks changed: three repetitions of the 27 regular cases, and an earlier two-repetition branch) and one judged repetition, whose scripted comparison is in `eval/reports/REPLAN-AB-20261116-234030.md`. Repetitions 2 and 3 of the branch and the earlier two-repetition branch were not judged. There is no demonstrated benefit, and on the row where `add_support` ran, latency and agent cost were a multiple of the baselines' (the report's cost table and `docs/REPLAN_DEMO.md` give the figures, read from the JSON files). Turning it on by default would therefore add cost and latency for a benefit that is not shown, and would change what the report describes.

**The pass rate of the regular cases is not comparable with the one of 12 November.** The judge changed after the second calibration: its verdict became a function of its scores, with language checked by code and caps for unsupported claims. The earlier rate came from another run, other cases, other agent prompts and the previous judge, and there are no human labels on those answers. A lower rate in today's generated block is therefore not attributed to the judge and not to the system. See [section 3 of the final report](FINAL_REPORT.md#3-does-the-judge-agree-with-a-human-v3) and [section 3.1](FINAL_REPORT.md#31-v2-re-scored-with-the-current-judge) for the three calibrations (V1, V2, V3: `eval/calibration/CALIBRATION_V1.md`, `eval/calibration/CALIBRATION_V2.md`, `eval/calibration/CALIBRATION_V3.md`), which used different judges and different samples and cannot be lined up as a trend, and [section 7, item 2](FINAL_REPORT.md#7-disclosures-and-limitations).

**What was not seen by the review and is not claimed as a grade.** The review could not see `observe`, `add_support`, the verifier, `interrupt()` for ticket approval, the webhook, RS256 with a JWKS, the OTLP traces or the CI, because none of them existed in `8c66a85`. This page does not estimate what grade they are worth.

**The CI.** The workflow has four jobs (`quality`, `test`, `alerts`, `docker`) in `.github/workflows/ci.yml`. The final report (section 7, item 13) says its first run on GitHub failed in two jobs, was fixed, and that the four jobs passed in the pull request of the branch `ci-fix`, and says nothing about `main`. That result is **not verifiable from a checkout**: it is the project's own account of a run on GitHub, and the tests only check that the workflow keeps its gates (`tests/test_ci_gates.py`).
